# loom 代码约定

术语以 [GLOSSARY.md](./GLOSSARY.md) 为准。修改代码后必须通过 `make test lint`。

## 折行与排版

按语义折行，不按列宽折行；行宽上限 120 只是兜底。不要用 `golines` 等工具自动折行——它只保证列宽，产出的形状难读。

- 调用有 4 个及以上参数，或单行超过 ~100 列：一个参数一行，右括号单独一行。
- 不要「续行」：禁止在一行里开括号写了部分参数后折行接着写剩余参数（`f(a, b,\n\tc)`）。
- 结构体字面量超过 3 个字段：一个字段一行。不要在字面量结束后同一行接着写其他参数（`}, db, log)`）。
- 参数很少的调用不要竖着拆；里面的字面量太长时，先提取为有名字的变量（`opts := ...; New(opts, deps)`）。
- slog：消息独占一行，key-value 不超过 2 对时可以整行写完；3 对及以上每对一行，键和值不拆开。
- 帮助文本、错误消息过长时先缩短或提取为常量，而不是折行。

## 函数与类型

- 参数超过 4 个时改用结构体（如 `store.APIKeySettings`、`pricing.Options`），而不是换一种折行方式。
- 「部分更新」用 `cur.Settings()` 取当前值，只改需要变的字段，再整体写回。
- 同一种东西只用一种写法（例如指标统一通过 `telemetry` 里的 helper 构造，按「名字、说明、标签」三行一块）。
- 依赖窄接口：业务包在自己包内声明需要的接口，不依赖 `store.Store` 全量接口。

## 分层

`transport → admission / ledger / account → pricing → store`；`app` 负责装配。
`transport` 只做线上格式与领域类型的互转，不写业务判断；`cmd/` 只做参数解析与调用 `internal/app`。
